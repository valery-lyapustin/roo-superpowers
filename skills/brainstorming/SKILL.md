# Мозговой штурм: от идей к дизайну

## Обзор

Превращай сырые идеи в полностью сформированные дизайны через структурированные вопросы и исследование альтернатив.

**Основной принцип:** Задавай вопросы для понимания, исследуй альтернативы, представляй дизайн постепенно для валидации.

**Объяви в начале:** "Я использую скилл Мозговой штурм для проработки твоей идеи в дизайн."

## Процесс

### Фаза 1: Понимание
- Проверь текущее состояние проекта в рабочей директории
- Задавай ОДИН вопрос за раз для уточнения идеи
- Предпочитай вопросы с вариантами ответов когда возможно
- Собирай: Цель, ограничения, критерии успеха

### Фаза 2: Исследование
- Предложи 2-3 разных подхода
- Для каждого: Основная архитектура, компромиссы, оценка сложности
- Если подходы имеют реальные компромиссы — смотри скилл `preserving-productive-tensions`

### Фаза 3: Дизайн
- Представляй дизайн постепенно
- Начни с высокоуровневой структуры
- Добавляй детали только после подтверждения направления
- Проверяй: "Это выглядит правильно пока?"

### Фаза 4: Настройка рабочего пространства (для реализации)
Когда дизайн одобрен и последует реализация:
- Объяви: "Я использую скилл Git Worktrees для настройки изолированного рабочего пространства."
- Переключись на скилл `using-git-worktrees`
- Следуй его процессу выбора директории, проверки безопасности и настройки
- Вернись сюда когда worktree готов

### Фаза 5: Передача планирования
Спроси: "Готов создать план реализации?"

Когда партнёр подтверждает:
- Объяви: "Я использую скилл Написание планов для создания плана реализации."
- Переключись на скилл `writing-plans`
- Создай детальный план в worktree

## Когда возвращаться к ранним фазам

**Можно и нужно идти назад когда:**
- Партнёр раскрывает новое ограничение в Фазе 2 или 3 → Вернись к Фазе 1
- Валидация показывает фундаментальный пробел в требованиях → Вернись к Фазе 1
- Партнёр ставит под сомнение подход в Фазе 3 → Вернись к Фазе 2
- Что-то не имеет смысла → Вернись и уточни

**Не форсируй линейное движение вперёд** когда возврат назад даст лучшие результаты.

## Связанные скиллы

**Во время исследования:**
- Когда подходы имеют реальные компромиссы: `preserving-productive-tensions`

**Перед предложением изменений в существующий код:**
- Понять почему он существует: `tracing-knowledge-lineages`

## Помни
- Один вопрос за сообщение в Фазе 1
- Применяй YAGNI безжалостно
- Исследуй 2-3 альтернативы перед выбором
- Представляй постепенно, валидируй по ходу
- Иди назад когда нужно — гибкость > жёсткая последовательность
- Объяви использование скилла в начале
