# Запрос код-ревью

Запускай подагента-ревьюера для выявления проблем до их накопления.

**Основной принцип:** Ревью рано, ревью часто.

## Когда запрашивать ревью

**Обязательно:**
- После каждой задачи в разработке через подагентов
- После завершения крупной фичи
- Перед слиянием в main

**Опционально но ценно:**
- Когда застрял (свежий взгляд)
- Перед рефакторингом (базовая проверка)
- После исправления сложного бага

## Как запросить

**1. Получи git SHA:**
```bash
BASE_SHA=$(git rev-parse HEAD~1)  # или origin/main
HEAD_SHA=$(git rev-parse HEAD)
```

**2. Запусти подагента-ревьюера через `new_task`:**

```
new_task(
  mode="ask",
  message="""
    Проведи код-ревью следующих изменений:

    ЧТО РЕАЛИЗОВАНО: {ЧТО_РЕАЛИЗОВАНО}
    ТРЕБОВАНИЯ: {ПЛАН_ИЛИ_ТРЕБОВАНИЯ}
    BASE_SHA: {BASE_SHA}
    HEAD_SHA: {HEAD_SHA}
    ОПИСАНИЕ: {ОПИСАНИЕ}

    Для каждой проблемы укажи:
    - Критическая: Ломает функциональность, проблемы безопасности
    - Важная: Должна быть исправлена перед продолжением
    - Незначительная: Хорошо бы исправить

    Верни: Сильные стороны, Проблемы (Критические/Важные/Незначительные), Оценку готовности
  """
)
```

**3. Действуй по обратной связи:**
- Исправляй Критические проблемы немедленно
- Исправляй Важные проблемы перед продолжением
- Записывай Незначительные для позже
- Возражай если ревьюер неправ (с обоснованием)

## Пример

```
[Только завершил Задачу 2: Добавить функцию верификации]

Ты: Давай запрошу код-ревью перед продолжением.

BASE_SHA=$(git log --oneline | grep "Задача 1" | head -1 | awk '{print $1}')
HEAD_SHA=$(git rev-parse HEAD)

[Запускаю подагента-ревьюера]
  ЧТО РЕАЛИЗОВАНО: Функции верификации и восстановления для индекса разговоров
  ТРЕБОВАНИЯ: Задача 2 из docs/plans/deployment-plan.md
  BASE_SHA: a7981ec
  HEAD_SHA: 3df7661
  ОПИСАНИЕ: Добавлены verifyIndex() и repairIndex() с 4 типами проблем

[Подагент возвращает]:
  Сильные стороны: Чистая архитектура, реальные тесты
  Проблемы:
    Важная: Отсутствуют индикаторы прогресса
    Незначительная: Магическое число (100) для интервала отчётности
  Оценка: Готов продолжать

Ты: [Исправляю индикаторы прогресса]
[Продолжаю к Задаче 3]
```

## Интеграция с рабочими процессами

**Разработка через подагентов:**
- Ревью после КАЖДОЙ задачи
- Выявляй проблемы до их накопления
- Исправляй перед переходом к следующей задаче

**Выполнение планов:**
- Ревью после каждого пакета (3 задачи)
- Получай обратную связь, применяй, продолжай

**Ad-hoc разработка:**
- Ревью перед слиянием
- Ревью когда застрял

## Красные флаги

**Никогда:**
- Пропускать ревью потому что "это просто"
- Игнорировать Критические проблемы
- Продолжать с неисправленными Важными проблемами
- Спорить с валидной технической обратной связью

**Если ревьюер неправ:**
- Возражай с техническим обоснованием
- Покажи код/тесты доказывающие что работает
- Запроси разъяснение
