# Разработка через подагентов

Выполняй план запуская свежего подагента на каждую задачу с код-ревью после каждой.

**Основной принцип:** Свежий подагент на задачу + ревью между задачами = высокое качество, быстрая итерация

## Обзор

**Отличие от Выполнения планов (параллельная сессия):**
- Та же сессия (нет переключения контекста)
- Свежий подагент на задачу (нет загрязнения контекста)
- Код-ревью после каждой задачи (ловим проблемы рано)
- Более быстрая итерация (нет человека в цикле между задачами)

**Когда использовать:**
- Остаёшься в этой сессии
- Задачи в основном независимы
- Хочешь непрерывный прогресс с воротами качества

**Когда НЕ использовать:**
- Нужно сначала проверить план (используй executing-plans)
- Задачи тесно связаны (лучше ручное выполнение)
- План требует пересмотра (сначала brainstorming)

## Процесс

### 1. Загрузи план

Прочитай файл плана, создай задачи в `update_todo_list` для всех задач.

### 2. Выполни задачу через подагента

Для каждой задачи запускай свежего подагента через `new_task`:

```
new_task(
  mode="code",
  message="""
    Ты реализуешь Задачу N из [файл-плана].

    Прочитай эту задачу внимательно. Твоя работа:
    1. Реализовать ровно то что указывает задача
    2. Написать тесты (следуя TDD если задача говорит)
    3. Верифицировать что реализация работает
    4. Сделать коммит своей работы
    5. Отчитаться

    Работай из: [директория]

    Отчёт: Что реализовал, что тестировал, результаты тестов, изменённые файлы, любые проблемы
  """
)
```

**Подагент отчитывается** с кратким изложением работы.

### 3. Проверь работу подагента

Запусти код-ревью через нового подагента:

```
new_task(
  mode="ask",
  message="""
    Проведи код-ревью следующих изменений:

    ЧТО РЕАЛИЗОВАНО: [из отчёта подагента]
    ТРЕБОВАНИЯ: Задача N из [файл-плана]
    BASE_SHA: [коммит до задачи]
    HEAD_SHA: [текущий коммит]

    Проверь:
    - Соответствие требованиям задачи
    - Качество кода и тестов
    - Потенциальные проблемы

    Верни: Сильные стороны, Проблемы (Критические/Важные/Незначительные), Оценку
  """
)
```

**Ревьюер возвращает:** Сильные стороны, Проблемы, Оценку

### 4. Применяй обратную связь ревью

**Если найдены проблемы:**
- Исправляй Критические проблемы немедленно
- Исправляй Важные проблемы перед следующей задачей
- Записывай Незначительные проблемы

**Запускай подагента исправления если нужно:**
```
new_task(mode="code", message="Исправь проблемы из код-ревью: [список проблем]")
```

### 5. Отметь завершённой, следующая задача

- Отметь задачу как завершённую в `update_todo_list`
- Переходи к следующей задаче
- Повторяй шаги 2-5

### 6. Финальное ревью

После завершения всех задач запусти финального ревьюера:
- Проверяет всю реализацию
- Проверяет выполнение всех требований плана
- Валидирует общую архитектуру

### 7. Завершение разработки

После прохождения финального ревью:
- Объяви: "Я использую скилл Завершение ветки разработки для завершения этой работы."
- Переключись на скилл `finishing-a-development-branch`
- Следуй ему для верификации тестов, представления вариантов, выполнения выбора

## Красные флаги

**Никогда:**
- Пропускать код-ревью между задачами
- Продолжать с неисправленными Критическими проблемами
- Запускать несколько подагентов реализации параллельно (конфликты)
- Реализовывать без чтения задачи плана

**Если подагент не справился с задачей:**
- Запусти подагента исправления с конкретными инструкциями
- Не пытайся исправить вручную (загрязнение контекста)

## Интеграция

**Работает в паре с:**
- `writing-plans` (создаёт план)
- `tdd` (подагенты следуют этому)

**Альтернатива:**
- `executing-plans` (параллельная сессия)
