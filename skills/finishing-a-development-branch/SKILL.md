# Завершение ветки разработки

## Обзор

Направляй завершение разработки представляя чёткие варианты и обрабатывая выбранный рабочий процесс.

**Основной принцип:** Верифицируй тесты → Представь варианты → Выполни выбор → Очисти.

**Объяви в начале:** "Я использую скилл Завершение ветки разработки для завершения этой работы."

## Процесс

### Шаг 1: Верифицируй тесты

**Перед представлением вариантов — убедись что тесты проходят:**

```bash
# Запусти набор тестов проекта
npm test / cargo test / pytest / go test ./...
```

**Если тесты падают:**
```
Тесты падают (N падений). Нужно исправить перед завершением:

[Покажи падения]

Нельзя продолжать со слиянием/PR пока тесты не пройдут.
```

Стоп. Не переходи к Шагу 2.

**Если тесты проходят:** Продолжай к Шагу 2.

### Шаг 2: Определи базовую ветку

```bash
# Попробуй общие базовые ветки
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

Или спроси: "Эта ветка отделилась от main — это правильно?"

### Шаг 3: Представь варианты

Представь ровно эти 4 варианта:

```
Реализация завершена. Что хочешь сделать?

1. Слить обратно в <базовая-ветка> локально
2. Запушить и создать Pull Request
3. Оставить ветку как есть (разберусь позже)
4. Отменить эту работу

Какой вариант?
```

**Не добавляй объяснений** — держи варианты краткими.

### Шаг 4: Выполни выбор

#### Вариант 1: Слить локально

```bash
# Переключись на базовую ветку
git checkout <базовая-ветка>

# Подтяни последнее
git pull

# Слей ветку фичи
git merge <ветка-фичи>

# Верифицируй тесты на результате слияния
<команда тестов>

# Если тесты проходят
git branch -d <ветка-фичи>
```

Затем: Очистка worktree (Шаг 5)

#### Вариант 2: Запушить и создать PR

```bash
# Запуши ветку
git push -u origin <ветка-фичи>

# Создай PR
gh pr create --title "<заголовок>" --body "$(cat <<'EOF'
## Краткое описание
<2-3 пункта что изменилось>

## План тестирования
- [ ] <шаги верификации>
EOF
)"
```

Затем: Очистка worktree (Шаг 5)

#### Вариант 3: Оставить как есть

Сообщи: "Оставляю ветку <название>. Worktree сохранён по адресу <путь>."

**Не очищай worktree.**

#### Вариант 4: Отменить

**Сначала подтверди:**
```
Это навсегда удалит:
- Ветку <название>
- Все коммиты: <список-коммитов>
- Worktree по адресу <путь>

Напечатай 'отменить' для подтверждения.
```

Жди точного подтверждения.

Если подтверждено:
```bash
git checkout <базовая-ветка>
git branch -D <ветка-фичи>
```

Затем: Очистка worktree (Шаг 5)

### Шаг 5: Очистка Worktree

**Для вариантов 1, 2, 4:**

Проверь находишься ли в worktree:
```bash
git worktree list | grep $(git branch --show-current)
```

Если да:
```bash
git worktree remove <путь-worktree>
```

**Для варианта 3:** Сохрани worktree.

## Краткий справочник

| Вариант | Слить | Запушить | Сохранить Worktree | Очистить ветку |
|--------|-------|------|---------------|----------------|
| 1. Слить локально | ✓ | - | - | ✓ |
| 2. Создать PR | - | ✓ | ✓ | - |
| 3. Оставить как есть | - | - | ✓ | - |
| 4. Отменить | - | - | - | ✓ (принудительно) |

## Распространённые ошибки

**Пропуск верификации тестов**
- **Проблема:** Слияние сломанного кода, создание падающего PR
- **Исправление:** Всегда верифицируй тесты перед предложением вариантов

**Открытые вопросы**
- **Проблема:** "Что делать дальше?" → неоднозначно
- **Исправление:** Представляй ровно 4 структурированных варианта

**Автоматическая очистка worktree**
- **Проблема:** Удаление worktree когда он может понадобиться (варианты 2, 3)
- **Исправление:** Очищай только для вариантов 1 и 4

**Нет подтверждения для отмены**
- **Проблема:** Случайное удаление работы
- **Исправление:** Требуй напечатанного подтверждения 'отменить'

## Красные флаги

**Никогда:**
- Продолжать с падающими тестами
- Сливать без верификации тестов на результате
- Удалять работу без подтверждения
- Принудительно пушить без явного запроса

**Всегда:**
- Верифицировать тесты перед предложением вариантов
- Представлять ровно 4 варианта
- Получать напечатанное подтверждение для варианта 4
- Очищать worktree только для вариантов 1 и 4
