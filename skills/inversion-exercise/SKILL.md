# Упражнение инверсии

## Обзор

Переворачивай каждое допущение и смотри что всё ещё работает. Иногда противоположное раскрывает истину.

**Основной принцип:** Инверсия обнажает скрытые допущения и альтернативные подходы.

## Краткий справочник

| Обычное допущение | Инвертированное | Что раскрывает |
|-------------------|----------|-----------------|
| Кэшировать для снижения задержки | Добавить задержку для включения кэширования | Паттерны debounce |
| Тянуть данные когда нужно | Толкать данные до того как нужно | Предзагрузка, eager loading |
| Обрабатывать ошибки когда возникают | Сделать ошибки невозможными | Системы типов, контракты |
| Строить фичи которые хотят пользователи | Убирать фичи которые не нужны пользователям | Простота >> добавление |
| Оптимизировать для обычного случая | Оптимизировать для худшего случая | Паттерны устойчивости |

## Процесс

1. **Перечисли основные допущения** — Что "должно" быть правдой?
2. **Инвертируй каждое систематически** — "Что если бы верно было противоположное?"
3. **Исследуй последствия** — Что мы делали бы по-другому?
4. **Найди валидные инверсии** — Какие реально работают где-то?

## Пример

**Проблема:** Пользователи жалуются что приложение медленное

**Обычный подход:** Сделать всё быстрее (кэширование, оптимизация, CDN)

**Инвертированный:** Намеренно замедлить некоторые вещи
- Debounce поиска (добавить задержку → включить лучшие результаты)
- Ограничение частоты запросов (добавить трение → предотвратить злоупотребления)
- Ленивая загрузка контента (задержка → уменьшить начальную загрузку)

**Понимание:** Стратегическая медлительность может улучшить UX

## Красные флаги что нужна эта техника

- "Есть только один способ сделать это"
- Форсируешь решение которое кажется неправильным
- Не можешь сформулировать почему подход необходим
- "Так просто делается"

## Помни

- Не все инверсии работают (тестируй границы)
- Валидные инверсии раскрывают контекстную зависимость
- Иногда противоположное — это ответ
- Ставь под сомнение утверждения "должно быть"
