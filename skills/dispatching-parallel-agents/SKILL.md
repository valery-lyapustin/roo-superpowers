# Параллельный запуск подагентов

## Обзор

Когда у тебя несколько несвязанных проблем (разные тестовые файлы, разные подсистемы, разные баги) — последовательное исследование тратит время. Каждое исследование независимо и может происходить параллельно.

**Основной принцип:** Запускай одного агента на независимую проблемную область. Пусть работают одновременно.

## Когда использовать

**Используй когда:**
- 3+ тестовых файла падают с разными первопричинами
- Несколько подсистем сломаны независимо
- Каждую проблему можно понять без контекста других
- Нет общего состояния между исследованиями

**Не используй когда:**
- Проблемы связаны (исправление одной может исправить другие)
- Нужно понять полное состояние системы
- Агенты будут мешать друг другу

## Паттерн

### 1. Определи независимые области

Группируй проблемы по тому что сломано:
- Тесты файла A: Поток одобрения инструментов
- Тесты файла B: Поведение пакетного завершения
- Тесты файла C: Функциональность прерывания

Каждая область независима — исправление одобрения инструментов не влияет на тесты прерывания.

### 2. Создай сфокусированные задачи для агентов

Каждый агент получает:
- **Конкретную область:** Один тестовый файл или подсистема
- **Чёткую цель:** Сделать эти тесты проходящими
- **Ограничения:** Не менять другой код
- **Ожидаемый вывод:** Краткое изложение что нашёл и исправил

### 3. Запускай параллельно

В Roo Code используй инструмент `new_task` для каждого агента:

```
new_task(mode="debug", message="Исправь падения в src/agents/agent-tool-abort.test.ts")
new_task(mode="debug", message="Исправь падения в src/batch-completion-behavior.test.ts")
new_task(mode="debug", message="Исправь падения в src/tool-approval-race-conditions.test.ts")
// Все три запускаются одновременно
```

### 4. Проверяй и интегрируй

Когда агенты возвращаются:
- Читай каждое краткое изложение
- Проверяй что исправления не конфликтуют
- Запускай полный набор тестов
- Интегрируй все изменения

## Структура промпта для агента

Хорошие промпты для агентов:
1. **Сфокусированные** — Одна чёткая проблемная область
2. **Самодостаточные** — Весь контекст нужный для понимания проблемы
3. **Конкретные по выводу** — Что должен вернуть агент?

```markdown
Исправь 3 падающих теста в src/agents/agent-tool-abort.test.ts:

1. "должен прерывать инструмент с захватом частичного вывода" — ожидает 'прервано в' в сообщении
2. "должен обрабатывать смешанные завершённые и прерванные инструменты" — быстрый инструмент прерван вместо завершения
3. "должен правильно отслеживать pendingToolCount" — ожидает 3 результата но получает 0

Это проблемы с таймингом/гонками условий. Твоя задача:

1. Прочитай тестовый файл и пойми что проверяет каждый тест
2. Определи первопричину — проблемы с таймингом или реальные баги?
3. Исправь:
   - Заменив произвольные таймауты на ожидание по событию
   - Исправив баги в реализации прерывания если найдены
   - Скорректировав ожидания теста если тестируется изменённое поведение

НЕ просто увеличивай таймауты — найди реальную проблему.

Верни: Краткое изложение что нашёл и что исправил.
```

## Распространённые ошибки

**❌ Слишком широко:** "Исправь все тесты" — агент теряется
**✅ Конкретно:** "Исправь agent-tool-abort.test.ts" — сфокусированная область

**❌ Нет контекста:** "Исправь гонку условий" — агент не знает где
**✅ Контекст:** Вставь сообщения об ошибках и названия тестов

**❌ Нет ограничений:** Агент может рефакторить всё
**✅ Ограничения:** "НЕ меняй продакшн-код" или "Исправь только тесты"

**❌ Расплывчатый вывод:** "Исправь это" — ты не знаешь что изменилось
**✅ Конкретный:** "Верни краткое изложение первопричины и изменений"

## Когда НЕ использовать

**Связанные проблемы:** Исправление одной может исправить другие — сначала исследуй вместе
**Нужен полный контекст:** Понимание требует видения всей системы
**Исследовательская отладка:** Ты ещё не знаешь что сломано
**Общее состояние:** Агенты будут мешать (редактируют одни файлы, используют одни ресурсы)

## Верификация

После возврата агентов:
1. **Проверяй каждое краткое изложение** — Понимай что изменилось
2. **Проверяй конфликты** — Редактировали ли агенты один и тот же код?
3. **Запускай полный набор** — Проверяй что все исправления работают вместе
4. **Точечная проверка** — Агенты могут делать систематические ошибки

## Реальный эффект

Из сессии отладки:
- 6 падений в 3 файлах
- 3 агента запущены параллельно
- Все исследования завершены одновременно
- Все исправления успешно интегрированы
- Ноль конфликтов между изменениями агентов
