# Верификация перед завершением

## Обзор

Заявлять что работа завершена без верификации — это нечестность, а не эффективность.

**Основной принцип:** Доказательства перед заявлениями, всегда.

**Нарушение буквы этого правила — это нарушение его духа.**

## Железный закон

```
НИКАКИХ ЗАЯВЛЕНИЙ О ЗАВЕРШЕНИИ БЕЗ СВЕЖИХ ДОКАЗАТЕЛЬСТВ ВЕРИФИКАЦИИ
```

Если ты не запускал команду верификации в этом сообщении — ты не можешь заявлять что она проходит.

## Функция-ворота

```
ПЕРЕД заявлением о любом статусе или выражением удовлетворения:

1. ОПРЕДЕЛИ: Какая команда доказывает это заявление?
2. ЗАПУСТИ: Выполни ПОЛНУЮ команду (свежую, полную)
3. ЧИТАЙ: Полный вывод, проверяй код выхода, считай падения
4. ВЕРИФИЦИРУЙ: Подтверждает ли вывод заявление?
   - Если НЕТ: Укажи фактический статус с доказательствами
   - Если ДА: Делай заявление С доказательствами
5. ТОЛЬКО ТОГДА: Делай заявление

Пропустить любой шаг = ложь, не верификация
```

## Распространённые провалы

| Заявление | Требует | Недостаточно |
|-------|----------|----------------|
| Тесты проходят | Вывод команды тестов: 0 падений | Предыдущий запуск, "должны пройти" |
| Линтер чист | Вывод линтера: 0 ошибок | Частичная проверка, экстраполяция |
| Сборка успешна | Команда сборки: код выхода 0 | Линтер проходит, логи выглядят хорошо |
| Баг исправлен | Тест исходного симптома: проходит | Код изменён, предположительно исправлен |
| Регрессионный тест работает | Верифицирован цикл красный-зелёный | Тест проходит один раз |
| Агент завершил | VCS diff показывает изменения | Агент сообщает "успех" |
| Требования выполнены | Построчный чеклист | Тесты проходят |

## Красные флаги — СТОП

- Использование "должен", "вероятно", "кажется"
- Выражение удовлетворения до верификации ("Отлично!", "Готово!", и т.д.)
- Собираешься делать коммит/пуш/PR без верификации
- Доверяешь отчётам агентов об успехе
- Полагаешься на частичную верификацию
- Думаешь "только на этот раз"
- Устал и хочешь закончить работу
- **ЛЮБЫЕ формулировки подразумевающие успех без запуска верификации**

## Предотвращение рационализации

| Отговорка | Реальность |
|--------|---------|
| "Должно работать теперь" | ЗАПУСТИ верификацию |
| "Я уверен" | Уверенность ≠ доказательство |
| "Только на этот раз" | Без исключений |
| "Линтер прошёл" | Линтер ≠ компилятор |
| "Агент сказал успех" | Верифицируй независимо |
| "Я устал" | Усталость ≠ оправдание |
| "Частичная проверка достаточна" | Частичная ничего не доказывает |
| "Другие слова, правило не применяется" | Дух важнее буквы |

## Ключевые паттерны

**Тесты:**
```
✅ [Запусти команду тестов] [Вижу: 34/34 проходят] "Все тесты проходят"
❌ "Должны пройти теперь" / "Выглядит правильно"
```

**Регрессионные тесты (TDD Красный-Зелёный):**
```
✅ Напиши → Запусти (проходит) → Откати исправление → Запусти (ДОЛЖЕН УПАСТЬ) → Восстанови → Запусти (проходит)
❌ "Я написал регрессионный тест" (без верификации красный-зелёный)
```

**Сборка:**
```
✅ [Запусти сборку] [Вижу: код выхода 0] "Сборка проходит"
❌ "Линтер прошёл" (линтер не проверяет компиляцию)
```

**Требования:**
```
✅ Перечитай план → Создай чеклист → Верифицируй каждый → Сообщи о пробелах или завершении
❌ "Тесты проходят, фаза завершена"
```

**Делегирование агентам:**
```
✅ Агент сообщает успех → Проверь VCS diff → Верифицируй изменения → Сообщи фактическое состояние
❌ Доверяй отчёту агента
```

## Когда применять

**ВСЕГДА перед:**
- ЛЮБЫМ вариантом заявлений об успехе/завершении
- ЛЮБЫМ выражением удовлетворения
- ЛЮБЫМ позитивным утверждением о состоянии работы
- Коммитом, созданием PR, завершением задачи
- Переходом к следующей задаче
- Делегированием агентам

## Итог

**Никаких сокращений для верификации.**

Запусти команду. Прочитай вывод. ЗАТЕМ делай заявление.

Это не обсуждается.
