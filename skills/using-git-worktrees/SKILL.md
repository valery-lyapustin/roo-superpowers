# Использование Git Worktrees

## Обзор

Git worktrees создают изолированные рабочие пространства разделяющие один репозиторий, позволяя работать над несколькими ветками одновременно без переключения.

**Основной принцип:** Систематический выбор директории + проверка безопасности = надёжная изоляция.

**Объяви в начале:** "Я использую скилл Git Worktrees для настройки изолированного рабочего пространства."

## Процесс выбора директории

Следуй этому порядку приоритетов:

### 1. Проверь существующие директории

```bash
# Проверяй в порядке приоритета
ls -d .worktrees 2>/dev/null     # Предпочтительно (скрытая)
ls -d worktrees 2>/dev/null      # Альтернатива
```

**Если найдена:** Используй её. Если обе существуют — `.worktrees` побеждает.

### 2. Проверь CLAUDE.md / README.md

```bash
grep -i "worktree.*директор" README.md 2>/dev/null
grep -i "worktree.*director" README.md 2>/dev/null
```

**Если указано предпочтение:** Используй его без вопросов.

### 3. Спроси пользователя

Если директория не существует и нет предпочтения:

```
Директория worktree не найдена. Где создать worktrees?

1. .worktrees/ (локально в проекте, скрытая)
2. ~/worktrees/<название-проекта>/ (глобальное расположение)

Что предпочитаешь?
```

## Проверка безопасности

### Для локальных директорий проекта (.worktrees или worktrees)

**ОБЯЗАТЕЛЬНО проверь .gitignore перед созданием worktree:**

```bash
# Проверь есть ли паттерн директории в .gitignore
grep -q "^\.worktrees/$" .gitignore || grep -q "^worktrees/$" .gitignore
```

**Если НЕ в .gitignore:**

По правилу "Исправляй сломанное немедленно":
1. Добавь соответствующую строку в .gitignore
2. Сделай коммит изменения
3. Продолжай создание worktree

**Почему критично:** Предотвращает случайный коммит содержимого worktree в репозиторий.

### Для глобальной директории (~/worktrees)

Проверка .gitignore не нужна — вне проекта полностью.

## Шаги создания

### 1. Определи название проекта

```bash
project=$(basename "$(git rev-parse --show-toplevel)")
```

### 2. Создай worktree

```bash
# Определи полный путь
case $LOCATION in
  .worktrees|worktrees)
    path="$LOCATION/$BRANCH_NAME"
    ;;
  ~/worktrees/*)
    path="~/worktrees/$project/$BRANCH_NAME"
    ;;
esac

# Создай worktree с новой веткой
git worktree add "$path" -b "$BRANCH_NAME"
cd "$path"
```

### 3. Запусти настройку проекта

Автоопределение и запуск соответствующей настройки:

```bash
# Node.js
if [ -f package.json ]; then npm install; fi

# Rust
if [ -f Cargo.toml ]; then cargo build; fi

# Python
if [ -f requirements.txt ]; then pip install -r requirements.txt; fi
if [ -f pyproject.toml ]; then poetry install; fi

# Go
if [ -f go.mod ]; then go mod download; fi
```

### 4. Верифицируй чистую базовую линию

Запусти тесты чтобы убедиться что worktree начинается чисто:

```bash
# Примеры — используй команду подходящую для проекта
npm test
cargo test
pytest
go test ./...
```

**Если тесты падают:** Сообщи о падениях, спроси продолжать или исследовать.

**Если тесты проходят:** Сообщи о готовности.

### 5. Сообщи о расположении

```
Worktree готов по адресу <полный-путь>
Тесты проходят (N тестов, 0 падений)
Готов реализовывать <название-фичи>
```

## Краткий справочник

| Ситуация | Действие |
|-----------|--------|
| `.worktrees/` существует | Используй (проверь .gitignore) |
| `worktrees/` существует | Используй (проверь .gitignore) |
| Обе существуют | Используй `.worktrees/` |
| Ни одна не существует | Проверь README.md → Спроси пользователя |
| Директория не в .gitignore | Добавь немедленно + коммит |
| Тесты падают при базовой линии | Сообщи о падениях + спроси |
| Нет package.json/Cargo.toml | Пропусти установку зависимостей |

## Распространённые ошибки

**Пропуск проверки .gitignore**
- **Проблема:** Содержимое worktree отслеживается, загрязняет git status
- **Исправление:** Всегда проверяй .gitignore перед созданием локального worktree

**Предположение о расположении директории**
- **Проблема:** Создаёт несоответствие, нарушает соглашения проекта
- **Исправление:** Следуй приоритету: существующая > README.md > спроси

**Продолжение с падающими тестами**
- **Проблема:** Нельзя отличить новые баги от уже существующих
- **Исправление:** Сообщи о падениях, получи явное разрешение продолжать

**Жёсткое кодирование команд настройки**
- **Проблема:** Ломается на проектах использующих другие инструменты
- **Исправление:** Автоопределение из файлов проекта (package.json и т.д.)

## Пример рабочего процесса

```
Ты: Я использую скилл Git Worktrees для настройки изолированного рабочего пространства.

[Проверяю .worktrees/ — существует]
[Проверяю .gitignore — содержит .worktrees/]
[Создаю worktree: git worktree add .worktrees/auth -b feature/auth]
[Запускаю npm install]
[Запускаю npm test — 47 проходят]

Worktree готов по адресу /home/user/myproject/.worktrees/auth
Тесты проходят (47 тестов, 0 падений)
Готов реализовывать фичу auth
```

## Красные флаги

**Никогда:**
- Создавать worktree без проверки .gitignore (локальный)
- Пропускать верификацию базовых тестов
- Продолжать с падающими тестами без вопроса
- Предполагать расположение директории когда неоднозначно
- Пропускать проверку README.md

**Всегда:**
- Следовать приоритету директорий: существующая > README.md > спроси
- Проверять .gitignore для локальных директорий
- Автоопределять и запускать настройку проекта
- Верифицировать чистую базовую линию тестов
