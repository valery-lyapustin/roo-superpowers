# Ожидание по условию

## Обзор

Нестабильные тесты часто угадывают тайминг с произвольными задержками. Это создаёт гонки условий где тесты проходят на быстрых машинах но падают под нагрузкой или в CI.

**Основной принцип:** Жди фактического условия которое тебя интересует, а не угадывай сколько времени это займёт.

## Когда использовать

**Используй когда:**
- Тесты имеют произвольные задержки (`setTimeout`, `sleep`, `time.sleep()`)
- Тесты нестабильны (иногда проходят, падают под нагрузкой)
- Тесты таймаутят при параллельном запуске
- Ожидаешь завершения асинхронных операций

**Не используй когда:**
- Тестируешь фактическое поведение тайминга (debounce, интервалы throttle)
- Всегда документируй ПОЧЕМУ если используешь произвольный таймаут

## Основной паттерн

```typescript
// ❌ ДО: Угадываем тайминг
await new Promise(r => setTimeout(r, 50));
const результат = getResult();
expect(результат).toBeDefined();

// ✅ ПОСЛЕ: Ждём условие
await waitFor(() => getResult() !== undefined);
const результат = getResult();
expect(результат).toBeDefined();
```

## Быстрые паттерны

| Сценарий | Паттерн |
|----------|---------|
| Ждать событие | `waitFor(() => events.find(e => e.type === 'DONE'))` |
| Ждать состояние | `waitFor(() => machine.state === 'ready')` |
| Ждать количество | `waitFor(() => items.length >= 5)` |
| Ждать файл | `waitFor(() => fs.existsSync(path))` |
| Сложное условие | `waitFor(() => obj.ready && obj.value > 10)` |

## Реализация

Универсальная функция опроса:
```typescript
async function waitFor<T>(
  condition: () => T | undefined | null | false,
  description: string,
  timeoutMs = 5000
): Promise<T> {
  const startTime = Date.now();

  while (true) {
    const result = condition();
    if (result) return result;

    if (Date.now() - startTime > timeoutMs) {
      throw new Error(`Таймаут ожидания ${description} после ${timeoutMs}мс`);
    }

    await new Promise(r => setTimeout(r, 10)); // Опрос каждые 10мс
  }
}
```

**Использование:**
```typescript
// Ждём конкретное событие
const событие = await waitFor(
  () => события.find(e => e.type === 'ЗАВЕРШЕНО'),
  'событие завершения',
  5000
);

// Ждём состояние машины
await waitFor(
  () => машина.state === 'готова',
  'машина в состоянии готова'
);
```

## Распространённые ошибки

**❌ Слишком частый опрос:** `setTimeout(check, 1)` — тратит CPU
**✅ Исправление:** Опрашивай каждые 10мс

**❌ Нет таймаута:** Бесконечный цикл если условие никогда не выполнится
**✅ Исправление:** Всегда включай таймаут с чётким сообщением об ошибке

**❌ Устаревшие данные:** Кэшируй состояние до цикла
**✅ Исправление:** Вызывай геттер внутри цикла для свежих данных

## Когда произвольный таймаут ПРАВИЛЬНЫЙ

```typescript
// Инструмент тикает каждые 100мс — нужно 2 тика для верификации частичного вывода
await waitForEvent(manager, 'TOOL_STARTED'); // Сначала: жди условие
await new Promise(r => setTimeout(r, 200));   // Затем: жди поведение с таймингом
// 200мс = 2 тика при интервале 100мс — задокументировано и обосновано
```

**Требования:**
1. Сначала жди триггерное условие
2. Основано на известном тайминге (не угадывание)
3. Комментарий объясняющий ПОЧЕМУ

- Больше никаких гонок условий
