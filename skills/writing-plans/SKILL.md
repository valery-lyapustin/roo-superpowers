# Написание планов реализации

## Обзор

Пиши исчерпывающие планы реализации предполагая что разработчик имеет нулевой контекст нашей кодовой базы. Документируй всё что им нужно знать: какие файлы трогать для каждой задачи, код, тестирование, документацию которую нужно проверить, как тестировать. Давай им полный план в виде небольших задач. DRY. YAGNI. TDD. Частые коммиты.

Предполагай что они опытный разработчик, но почти ничего не знают о нашем инструментарии или предметной области.

**Объяви в начале:** "Я использую скилл Написание планов для создания плана реализации."

**Контекст:** Это должно запускаться в выделенном worktree (созданном скиллом brainstorming).

**Сохраняй планы в:** `docs/plans/ГГГГ-ММ-ДД-<название-фичи>.md`

## Гранулярность задач

**Каждый шаг — одно действие (2-5 минут):**
- "Напиши падающий тест" — шаг
- "Запусти его чтобы убедиться что падает" — шаг
- "Реализуй минимальный код для прохождения теста" — шаг
- "Запусти тесты и убедись что проходят" — шаг
- "Сделай коммит" — шаг

## Заголовок документа плана

**Каждый план ОБЯЗАН начинаться с этого заголовка:**

```markdown
# План реализации [Название фичи]

> **Для Roo:** Используй скилл `executing-plans` для реализации этого плана задача за задачей.

**Цель:** [Одно предложение описывающее что это строит]

**Архитектура:** [2-3 предложения о подходе]

**Технологический стек:** [Ключевые технологии/библиотеки]

---
```

## Структура задачи

```markdown
### Задача N: [Название компонента]

**Файлы:**
- Создать: `точный/путь/к/файлу.py`
- Изменить: `точный/путь/к/существующему.py:123-145`
- Тест: `tests/точный/путь/к/тесту.py`

**Шаг 1: Напиши падающий тест**

```python
def test_конкретное_поведение():
    результат = функция(входные_данные)
    assert результат == ожидаемое
```

**Шаг 2: Запусти тест чтобы убедиться что падает**

Запусти: `pytest tests/путь/тест.py::test_название -v`
Ожидается: FAIL с "функция не определена"

**Шаг 3: Напиши минимальную реализацию**

```python
def функция(входные_данные):
    return ожидаемое
```

**Шаг 4: Запусти тест чтобы убедиться что проходит**

Запусти: `pytest tests/путь/тест.py::test_название -v`
Ожидается: PASS

**Шаг 5: Сделай коммит**

```bash
git add tests/путь/тест.py src/путь/файл.py
git commit -m "feat: добавить конкретную фичу"
```
```

## Помни
- Всегда точные пути к файлам
- Полный код в плане (не "добавь валидацию")
- Точные команды с ожидаемым выводом
- DRY, YAGNI, TDD, частые коммиты

## Передача выполнения

После сохранения плана предложи выбор выполнения:

**"План готов и сохранён в `docs/plans/<имя_файла>.md`. Два варианта выполнения:**

**1. Через подагентов (эта сессия)** — Запускаю свежего подагента на каждую задачу, ревью между задачами, быстрая итерация

**2. Параллельная сессия (отдельная)** — Открой новую сессию с executing-plans, пакетное выполнение с контрольными точками

**Какой подход?"**

**Если выбран вариант через подагентов:**
- Используй скилл `subagent-driven-development`
- Оставайся в этой сессии
- Свежий подагент на задачу + код-ревью

**Если выбрана параллельная сессия:**
- Направь открыть новую сессию в worktree
- Новая сессия использует скилл `executing-plans`
